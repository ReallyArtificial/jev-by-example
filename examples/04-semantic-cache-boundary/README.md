# 04 · Almost the same question. Dangerously different answer.

A semantic cache must distinguish “last month” from “right now.”

**Pattern:** Hard partition checks followed by answer interchangeability.

## Why this decision matters

Embedding similarity is useful for finding cache candidates. It is insufficient to establish whether an answer can be reused.

## Run it

From the repository root:

```sh
npm start -- run 04
npm start -- request 04 --case paraphrase
npm start -- run 04 --case paraphrase --live
```

The first command uses authored response fixtures. The last needs a TypeSafe API key and makes a real request. No command performs the proposed downstream action.

## Read the evidence

Example input: **paraphrase**.

```json
{
  "current": {
    "tenant": "studio",
    "policyVersion": 3,
    "question": "How long do staging logs stay available?"
  },
  "cached": {
    "tenant": "studio",
    "policyVersion": 3,
    "question": "What is the staging log retention period?",
    "answer": "Staging logs are retained for seven days."
  },
  "ageSeconds": 30,
  "ttlSeconds": 300,
  "similarity": 0.96
}
```

## Ask focused questions

### `interchangeable` · noul

Could `cached.answer` answer `current.question` without changing its time scope, subject, requested detail, or language? Compare with `cached.question`.


All these questions see the same state independently. None sees another question's answer. Review [example.mjs](example.mjs) for the policy and [cases.mjs](cases.mjs) for the full case set.

## Follow the policy

The authored fixture produces this application result:

```json
{
  "action": "reuse-candidate",
  "reason": "A candidate must satisfy the teaching threshold for answer interchangeability."
}
```

The `reason` is written by application code, not generated by Jev. Fixture numbers illustrate policy branches; they are not measurements or predictions of model behavior.

## Try the contrasting cases

| Case | What changes | Intended policy outcome |
| :-- | :-- | :-- |
| `paraphrase` | Same scope, wording changed. | `reuse-candidate` |
| `time-shift` | The numbers are from a different period. | `bypass` |
| `wrong-tenant` | Hard rejection without a model call. | `bypass` |
| `expired` | High similarity cannot extend a TTL. | `bypass` |

These intended outcomes are author judgments. A live disagreement is evidence to inspect, not a result to quietly relabel.

## Change one thing

Change only the time period, language, policy version, or tenant. Tenant and expiry changes should be settled by code before a request exists.

Edit the case state, inspect the request, then run with `--live` to see what Jev does. Editing only the state in fixture mode does **not** change its scripted response. Change fixture values separately when testing a policy branch.

## Where it stops

A teaching cache gate, not a Freeport integration. Tenant, policy version, and expiry checks run before any candidate is sent to Jev.

**Known failure mode:** A compatible question can still have an incorrect cached answer. This example checks reuse conditions, not the answer’s truth.

The included baseline is intentionally limited. Its purpose is to expose a particular shortcut, not to represent the strongest alternative. See [evaluation notes](../../docs/evaluation.md).
