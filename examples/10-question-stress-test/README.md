# 10 · Does the decision survive a harmless rewrite?

Swap option order. Rephrase the question. Keep the evidence fixed.

**Pattern:** Metamorphic checks for question sensitivity.

## Why this decision matters

A single successful call says little about stability. Compare equivalent requests and include a genuine evidence change as a control.

## Run it

From the repository root:

```sh
npm start -- run 10
npm start -- request 10 --case original
npm start -- run 10 --case original --live
```

The first command uses authored response fixtures. The last needs a TypeSafe API key and makes a real request. No command performs the proposed downstream action.

## Read the evidence

Example input: **original**.

```json
{
  "request": "Prepare a draft release announcement in a local file. Do not publish or send it anywhere."
}
```

## Ask focused questions

### `intent` · choice

Which publication intent does `request` explicitly express?

```json
{
  "local_only": "The request explicitly allows a local draft only and excludes publication.",
  "publish_requested": "The request explicitly asks to publish the result.",
  "unclear": "Publication intent is missing or contradictory."
}
```


All these questions see the same state independently. None sees another question's answer. Review [example.mjs](example.mjs) for the policy and [cases.mjs](cases.mjs) for the full case set.

## Follow the policy

The authored fixture produces this application result:

```json
{
  "action": "local-draft",
  "reason": "Classify intent only; no publication is performed."
}
```

The `reason` is written by application code, not generated by Jev. Fixture numbers illustrate policy branches; they are not measurements or predictions of model behavior.

## Try the contrasting cases

| Case | What changes | Intended policy outcome |
| :-- | :-- | :-- |
| `original` | The original request and question. | `local-draft` |
| `reordered-options` | Only the order of options changes. | `local-draft` |
| `paraphrased-question` | Only the question wording changes. | `local-draft` |
| `changed-evidence` | A positive control: publication is now explicitly requested. | `publication-review` |

These intended outcomes are author judgments. A live disagreement is evidence to inspect, not a result to quietly relabel.

## Change one thing

Add another equivalent question wording to the comparison group. Run repeated live reports with a pinned model and check both action agreement and the underlying distributions.

Edit the case state, inspect the request, then run with `--live` to see what Jev does. Editing only the state in fixture mode does **not** change its scripted response. Change fixture values separately when testing a policy branch.

## Where it stops

Four small authored cases are not a robustness benchmark. Repeated calls and a larger independent dataset are needed to measure reliability.

**Known failure mode:** Stable answers can be consistently wrong. Agreement across variants must be read alongside the human-authored intended outcomes.

The included baseline is intentionally limited. Its purpose is to expose a particular shortcut, not to represent the strongest alternative. See [evaluation notes](../../docs/evaluation.md).
