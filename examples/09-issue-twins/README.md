# 09 · Same symptom, different bug

Two “checkout hangs” issues need not share a cause.

**Pattern:** Distinguish investigation links from duplicate closure.

## Why this decision matters

Deduplication by title can erase evidence. Compare causal signatures, environments, and workarounds while keeping uncertainty explicit.

## Run it

From the repository root:

```sh
npm start -- run 09
npm start -- request 09 --case same-title-different-cause
npm start -- run 09 --case same-title-different-cause --live
```

The first command uses authored response fixtures. The last needs a TypeSafe API key and makes a real request. No command performs the proposed downstream action.

## Read the evidence

Example input: **same-title-different-cause**.

```json
{
  "first": {
    "title": "Checkout hangs",
    "detail": "Server trace waits for DB pool; all browsers affected; restarting the pool helps."
  },
  "second": {
    "title": "Checkout hangs",
    "detail": "Browser extension blocks payment.js; server never receives checkout; disabling the extension fixes it."
  }
}
```

## Ask focused questions

### `relationship` · choice

What relationship is supported between `first` and `second`, considering their traces, trigger, and workaround rather than title alone?

```json
{
  "shared_cause": "Both reports provide specific matching evidence of the same cause.",
  "shared_symptom": "The symptom overlaps but causes differ or no shared cause is established.",
  "unrelated": "The reports concern different failures.",
  "insufficient": "There is too little evidence to determine a relationship."
}
```


All these questions see the same state independently. None sees another question's answer. Review [example.mjs](example.mjs) for the policy and [cases.mjs](cases.mjs) for the full case set.

## Follow the policy

The authored fixture produces this application result:

```json
{
  "action": "keep-separate",
  "reason": "A proposed relationship is not authority to close an issue."
}
```

The `reason` is written by application code, not generated by Jev. Fixture numbers illustrate policy branches; they are not measurements or predictions of model behavior.

## Try the contrasting cases

| Case | What changes | Intended policy outcome |
| :-- | :-- | :-- |
| `same-title-different-cause` | An exhausted pool and a blocked script are different investigations. | `keep-separate` |
| `different-title-matching-trace` | Useful linkage despite different wording. | `link-for-investigation` |
| `no-reproduction` | Two vague reports do not establish a cause. | `ask-for-evidence` |

These intended outcomes are author judgments. A live disagreement is evidence to inspect, not a result to quietly relabel.

## Change one thing

Keep the titles identical while changing the traces. Then make titles different but keep the precise causal signature. Neither result should close an issue.

Edit the case state, inspect the request, then run with `--live` to see what Jev does. Editing only the state in fixture mode does **not** change its scripted response. Change fixture values separately when testing a policy branch.

## Where it stops

Suggests an investigation relationship only. Never closes, edits, or comments on a GitHub issue.

**Known failure mode:** Matching logs can result from a shared downstream symptom. An apparent duplicate still needs a maintainer to confirm.

The included baseline is intentionally limited. Its purpose is to expose a particular shortcut, not to represent the strongest alternative. See [evaluation notes](../../docs/evaluation.md).
